# OPAirDrop

为 Android 手机接入 Apple AirDrop 的独立应用。以普通 APK 安装，不需要 Magisk 模块、不需要 LSPosed，也不改系统分区——需要的只是 root，以及一次驱动安装。

协议栈自己实现：mDNS 发现、BLE 广播唤起、TLS 1.3 握手与证书指纹钉住、`/Discover` `/Ask` `/Upload` 三个端点、cpio 归档与 DVZip 分块，全部在手机本地完成，不经过一加互传、Quick Share、Mosey，也不依赖任何 Google 服务。

## 功能

- **发送文件**：从系统分享面板选「发送到 iPhone」，或在首页点「发送文件」直接选文件（可多选）。面板在附近设备里列出 Apple 设备，点一下即发；对方确认后进度环按真实字节走，随时可以取消。
- **接收文件**：打开后前台常驻，8770 端口在听、mDNS 与 BLE 广播同时在场，不需要停在任何页面上。iPhone 发起时通知上给「接受 / 拒绝」两个键，30 秒无人应答按放弃处理——不替人做决定。
- **控制中心磁贴**：磁贴上的【AirDrop】就是接收开关，与首页「接收文件」那一行是同一份状态。开，服务在跑、端口在听、广播在发；关，三样一起停。没有十分钟到期这回事。
- **实时通知**：Android 16 的实时通知跟着真实进度走，ColorOS 把它画在流体云的位置，收完切成结果卡片。系统不愿意提升时它仍是一条带进度的常驻通知，所以这条路没有失败态。
- **内核驱动随包**：APK 自带四个内核模块、`wonder-ven` 与拉起脚本。功能页一键安装／卸载，装载前逐个校验 SHA-256，装完把脚本回执写在卡片上；卸载即恢复原厂驱动与网络环境。
- **按类型落盘**：照片与视频进 `DCIM/AirDrop`（相册直接扫得到），其余进 `Download/AirDrop`；也可以指定一个目录让所有文件都进去。同名不覆盖，默认加编号另存。
- **失败有话说**：对方拒绝、邀请过期、身份指纹不符、文件存不下，各是一句话，而不是一句笼统的「传输失败」。
- **三页界面**：首页给状态（传输、环境、设备信息），功能页给动作（驱动、射频、保存位置、设备显示），设置页给值（名字、目录、各类超时与上限，改完保存生效）。

## 适配基线

| 项目 | 当前配置 |
| --- | --- |
| 验证机型 | 一加 13（PJZ110），ColorOS V17.0.0 |
| Android | 16（API 37）；`minSdk 35`，`targetSdk 37` |
| 架构 | `arm64-v8a` |
| Root | 必需。KernelSU、KernelSU Next、APatch、Magisk 均可识别，首页直接报出管理器与版本 |
| 无线 | Qualcomm WLAN 平台；AWDL 固定信道 149（5745 MHz），20 MHz 带宽 |
| 蓝牙 | 需要 BLE 广播：iPhone 要先在蓝牙上听到这条广播，才会把 AWDL 上的 AirDrop 服务拉起来。没有 BLE 的机器装得上，但发现不了对端 |
| 版本 | 1.0.0（versionCode 10000） |

驱动与射频是硬前提：接收要 `wonder0` 在、8770 在听，发送要有多播出得去的网卡。首页「环境」那一行给出 root 状态，功能页给出驱动状态（未安装 / 已就绪 / 一半 / 失败），两处都不靠猜。

三组权限各管一件事，缺了会缺得很有针对性：

- **通知**：接收状态、邀请确认、进度与结果。应用不会自己弹权限框，需要到系统设置里为本应用打开——这条没开，接收端还在听，但邀请没有人能应答，30 秒后按放弃处理。
- **附近的设备**（蓝牙广播与连接）：用 BLE 广播叫醒 iPhone。未授权时链路仍可被已经知道地址的对端连上，但发现不了新设备。第一次进发送页时应用会申请一次。
- **网络与组播**：发现与传输，安装即授予，无需操作。

## 使用入口

第一次使用：

1. 安装 APK 并打开。到系统设置里给本应用打开通知；顺手确认「附近的设备」也是允许。
2. 看首页「环境 → root 权限」：显示「已获取」，副标题是授权管理器与版本；显示「未获取」就去管理器里给本应用授权。
3. 进功能页 → 驱动 → 【安装】。约半分钟，中途 Wi-Fi 会断一下（驱动不能在 Wi-Fi 活着时替换）。装好后右边胶囊变「已就绪」。
4. 在控制中心编辑页把【AirDrop】拖进快捷开关并点亮；或者回首页点「接收文件」那一行的胶囊。
5. 在 iPhone 上把 AirDrop 设为「所有人」（控制中心里那项，10 分钟有效），屏幕保持解锁亮着；从相册或文件里选文件分享，在列表里选本机，本机通知上按「接受」。

### 接收

接收端一次只服务一台设备，第二台排队，不会两路同时往同一个目录里写。接受之后进度同时出现在通知与实时通知上；收完的结果卡片写清楚文件名、大小、落在哪个目录。

拒绝与超时在发送端看来都是失败，在本机是两句话：拒绝是「已拒绝」，超时是「邀请已过期」。后者刻意不写成拒绝——没人看见这条邀请，不等于他拒绝了你。

### 发送

两条入口，一条路径：系统分享面板，或首页「发送文件」的文件选择器。选完之后都交给同一个发送页。

面板先显示「正在搜索附近设备……」，设备出现后点头像，等对方在 iPhone 上确认，环走完写「发送完成」。发送不需要本机处于接收状态，也不需要打开接收开关——那是接收端的事，发送端不欠它任何前提。

### 保存位置

| 收到的东西 | 落在哪 |
| --- | --- |
| 照片、视频 | `DCIM/AirDrop` |
| 其余一切：文档、压缩包、安装包、无扩展名的文件 | `Download/AirDrop` |
| 功能页「接收文件保存位置」填了目录 | 全部进那一个目录，不再分类型 |

同名文件默认并排留两份（`IMG_0001.jpg` 与 `IMG_0001 (1).jpg`），不覆盖。卡片上报的是落盘后回查到的真名，不是提交时的名字——所以加了编号也照实说。

## 已知限制

- **只在一加 13 上验证过。** 换机型要换随包的驱动与补丁，不是改一个设置就能跑。
- **iPhone 那边有两件事要做**：控制中心把 AirDrop 设为「所有人」（10 分钟有效），屏幕保持解锁亮着——锁屏后 iPhone 会暂时离开这条直连链路。本机这一侧同时发 mDNS 公告与 BLE 广播去叫醒它，但 BLE 是 2026-11-16 才接上的，真机端到端仍在复验。
- **速度由对端决定，不是本机的上限。** 接收约 80–88 KB/s（受 iPhone 的 AWDL 占空比限制），发送约 430 KB/s（受对端通告的接收窗口限制）。本机这一侧的瓶颈已经排除：不经无线电的自测环路能跑到 25 MB/s 以上。
- **每次重启后要重装一次驱动**（约半分钟）。应用没有开机自启，重启后需要重新打开接收。
- **证书指纹「相符也照常发」那一支还没在真实 iPhone 上走过。**「不符就拒」已经用错误指纹的握手验过，能给出可读原因。
- 多文件、超大文件、锁屏状态、传输中断电这些场景还没有全覆盖。
- 尚未发布正式 Release，也没有上架任何应用商店。

## 项目结构

```text
repo-OPAirDrop/
├── crates/            Rust 协议栈，八个 crate，协议知识只在这里
│   ├── bplist/        Apple 二进制 plist 读写
│   ├── cpio/          cpio odc/newc、DVZip 分块、gzip 识别
│   ├── mdns/          DNS 报文编解码
│   ├── http/          双向流式 HTTP/1.1 解析
│   ├── awdl/          AWDL 数据面、/dev/tun 与 AF_PACKET、awdld 守护进程
│   ├── airdrop/       三端点语义、客户端、服务端、收件箱
│   ├── settings/      参数表：键、区间、文案三合一
│   └── ffi/           C ABI 与 JNI，Java 侧唯一入口
├── android/           Android 应用
│   ├── app/           三页界面、发送页、接收服务、磁贴、驱动安装
│   ├── kernel-assets/ 随包内核模块与拉起脚本
│   └── build.sh       一条命令出 APK：先 Rust，后 Gradle
├── tools/             链路拉起、抓包与真机自测脚本
├── CHANGELOG.md
└── LICENSE
```

界面没有 XML 布局，全部代码绘制；`dependencies` 故意留空——没有 AndroidX、没有 Kotlin，APK 里只有框架类和那一个 `.so`。`crates/ffi/jvm` 下的 Java 类与 `android/app` 一起编进 APK。

## 开发入口

在仓库根目录：

```sh
# 出包：先交叉编译 aarch64 的 Rust，再打 APK
bash android/build.sh assembleDebug
bash android/build.sh clean

# 全量测试
cargo test --workspace          # 419 passed / 0 failed（1 ignored）
bash crates/ffi/jvm/check.sh    # 381 条 JVM 断言，桌面 JVM + -Xcheck:jni
```

JDK、SDK 与 Gradle 都放在 `tools/` 下，脚本按名字取而不查 `PATH`，可以用 `JAVA_HOME`、`GRADLE_BIN`、`CARGO_BIN` 覆盖。真机脚本在 `tools/`：`awdl-stack.sh` 拉起链路，`capture.sh` 抓包，`awdld-probe.sh` 看守护进程状态。
